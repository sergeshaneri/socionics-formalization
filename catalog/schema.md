# Схема каталога

Каталог описывает исследовательские артефакты и отдельно учитывает источники, файлы-представления, экземпляры пакетов и исключения. ID артефакта (`A0001`…) назначается один раз по реестру и не кодирует тему. ID источника (`SRC0001`…) отделён от ID артефакта.

## Карточка `artifacts/Axxxx/card.md`

YAML-заголовок содержит:

- `id`, `title`, `kind`;
- `source_paths` — repo-relative пути исходных файлов;
- `representations` — файлы, которые с оговорённым основанием считаются представлениями того же артефакта;
- `documented_date` — явно указанная в тексте/README дата исследования; иначе `не установлено`;
- `origin`, `model`, `prompt` — происхождение на уровне отдельного артефакта. Общая атрибуция коллекции GPT Astra/Sol не определяет модель конкретного файла;
- `topics`, `related_artifacts` — предварительные темы и типизированные связи с основанием.

Текст карточки отделяет цель и заявленные результаты от проверок каталогизатора. Для заявлений указывается раздел-основание. Уровень чтения: `обзорное`, `полное` либо специальное описание фактически просмотренных частей. Карточка не присваивает всему отчёту статус «доказано».

## Манифест `manifest.json`

Для каждого физического файла фиксируются repo-relative путь, роль, размер в байтах и SHA-256. Для ZIP дополнительно фиксируются список членов, размер распакованных данных, SHA-256 каждого члена, проверка CRC, проверка путей и сверка доступных внутренних манифестов. Размер `0` отличается от отсутствующего значения. Если путь из манифеста не найден, но SHA-256 и размер совпадают с членом под другим путём, это записывается как совпадение содержимого при несовпадении имени, а не как точное совпадение или отсутствие содержимого. Манифесты ZIP читаются без извлечения. Сохранённые отчёты `PASS` не заменяют новый запуск.

## Проверка `verification.md`

Записываются только выполненные действия: чтение и его глубина, проверка доступности/целостности, фактический результат запуска. Отдельно указываются невыполненные математическая проверка и повторный запуск.

## Реестр `inventory.json`

Реестр содержит одну запись на каждый физический файл выбранного охвата. Файл получает ссылку на карточку, пометку источника, роль в пакете либо явное исключение. Точные дубликаты устанавливаются SHA-256, а не именем. ZIP-члены учтены внутри манифеста пакета; они не считаются отдельными файлами рабочей копии.

`expected_artifacts` отдельно фиксирует файлы и пакеты, наличие которых прямо следует из отчёта, но которые отсутствуют или не сопоставлены в выбранном охвате. Это записи об ожиданиях, а не физические файлы. Для каждой указываются владелец, основание, ожидаемые/наблюдаемые/недостающие члены и возможные кандидаты.

Статусы ожиданий:

- `absent_in_scope` — соответствующий пакет в выбранном охвате не найден;
- `partial_candidate` — кандидат содержит только часть заявленных членов;
- `partial_unverified` — обнаружен возможный отдельный результат, но связь с выпуском не подтверждена;
- `candidate_not_verified` — есть содержательно близкий пакет, который не считается тем же выпуском;
- `inputs_absent_from_scope` — для заявленного повтора отсутствуют исходные материалы или программа.
- `incomplete_by_internal_manifest` — внутренний манифест архива перечисляет файлы, которые отсутствуют либо найдены под другими именами; совпадение по SHA-256 отражается отдельно.

`expected-artifacts.md` — читательская сводка этих записей; количества строятся из машинного реестра.

## Отношения

Допустимые значения: `accompanies`, `contains_report_copy`, `is_representation_of`, `byte_identical_copy_of`, `corrects`, `supersedes`, `uses`, `supports`, `contradicts`, `possibly_related`, `possibly_repaired_by`. Для содержательных и неопределённых связей карточка указывает основание. Различающиеся тексты не объединяются автоматически в одну редакцию.

## Статусы

- Артефакт: `found_readable`, `damaged`, `incomplete`.
- Проверка: `not_run`, `integrity_only`, `spot_check`, `rerun`.
- Основание утверждения: `definition`, `claimed_proof`, `proof_reviewed`, `finite_computation_claimed`, `finite_computation_rerun`, `hypothesis`, `interpretation`.

Каталогизация не является математическим аудитом корпуса.
